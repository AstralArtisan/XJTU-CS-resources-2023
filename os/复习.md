# Introduction

OS: A program that acts as an intermediary between a user of a computer and the computer hardware. 操作系统是管理和控制计算机系统中软硬件资源，合理组织计算机工作流程，方便用户操作使用机器的程序的集合。

System's Four components: Hardware, OS, Application programs, Users

OS is a resource allocator, a control program.

Dual-mode operation allows OS to protect itself and other system components. 
User mode: can only execute normal instructions, but not privileged instructions. (mode bit on) 
Kernel mode: can execute all instructions. Only OS processes should be executing in kernel mode. (mode bit off)

System call: a trap that changes from user mode to kernel mode, executes the privileged IO command, returns from system call and reverts back to user mode to continue execution.

<img src="assets/image-20251219140858438.png" alt="image-20251219140858438" style="zoom:50%;" />

Bus: Allows devices both inside and attached to the system unit to communicate with each other.

Interrupt: A signal to the CPU to tell it about the occurrence of a major event.
Program interrupt (traps): user request/error
I/O interrupt: I/O related events
Timer interrupt: time out

Timer: A simple way to prevent infinite loop and resources hogging by processes

Timer interrupt handler: clock routine. Used for process scheduling and resource management

Synchronous I/O: user waits until I/O completes.

Asynchronous I/O: user continues without waiting for I/O completion. When I/O completed, program will receive an interrupt.

Storage structure: Main memory, Secondary storage, Magnetic disks

Caching: copying information into faster storage system; main memory can be viewed as a last cache for secondary storage

Multiprocessors: Asymmetric and symmetric multiprocessing

Multicore: shared cache, I/O interface and date packet

Clustered systems: multiple systems working together



Simple batch(批) processing: <img src="assets/image-20251219142352744.png" alt="image-20251219142352744" style="zoom:33%;" />

multiprogramming: Programs are executed in interleaved manner by the CPU.

Multiplied batch processing system: several jobs are kept in main memory at the same time, and the CPU is multiplexed among them.

Time-sharing system: Same as multiprogramming, but system is interactive(交互的), so each process must get CPU without waiting for too long.

Real-time system: A time-sharing system where processes have completion deadlines that must be met. (hard and soft)

Network operating system: add the networking capability to OS

Distributed system: Operated upon a collection of computers scattered across the network.

Parallel system: multiprocessor systems with more than one CPU in close communication. (shared)

SMP: symmetric multiprocessing

embedded OS

批处理系统：脱机操作，成批处理，多道程序，无交互性

分时系统：交互性，同时性，独立性，及时性

实时系统：实时时钟管理，连续人机对话，过载防护，安全，资源利用率低



多道：允许多作业同时进入内存轮流交替占用CPU

OS components: processor manager, memory manager, file manager, device manager

**Process: A program in execution.**(An execution environment with restricted rights.) Program is a passive entity, process is an active entity.

Protection: A mechanism for controlling access of processes or users to resources defined by the system.

Security: The defense of the computer system against internal and external attacks.



# OS Structures

Services: User interface(UI): Command-line(CLI), Graphics user interface(GUI), Batch

Program execution: The system must be able to load a program into memory and to run that program, end execution, either normally or abnormally

I/O operations: A running program may require I/O, which may involve a file or an I/O device

File-system manipulation: Obviously, programs need to read and write files and directories, create and delete them, search them, list file information, permission management

Communications: Processes may exchange information, on the same computer or between computers over a network (shared memory or message passing)

Error detection: OS should ensure correct and consistent computing

Resource allocation: When multiple users or multiple jobs running concurrently, resources must be allocated to each of them

Accounting: To keep track of which users use how much and what kinds of computer resources

Protection and security: The owners of information stored in a multiuser or networked computer system may want to control use of that information, concurrent processes should not interfere with each other
**Protection** involves ensuring that all access to system resources is controlled.
**Security** of the system from outsiders requires user authentication, extends to defending external IO devices from invalid access attempts.



Command Line Interface(CLI) or command interpreter allows direct command entry.

GUI: desktop interface

**System calls: Programming interface to the services provided by the OS**, accessed by programs via API

When executes the system call, the system call interface generates a software trap. CPU switches to kernel mode.

Passing parameters: registers, stored in a block/table in memory, or pushed/popped to and from the stack.

System programs: File manipulation, status information, file modification, programming language support, program loading and execution, communications



MD-DOS: written to provide the most functionality in the least space

Layered approach: divide the system into a number of layers

Microkernel system structure:

Modules: uses object-oriented approach, each core component is separate, each talks to the others over known interfaces, each is loadable as needed within the kernel.

Hybrid systems

Virtual machines: take the layered approach to its logical conclusion. It treats hardware and the OS kernel as though they were all hardware. Host creates the illusion that a process has its own processor and virtual memory, guest provided with a virtual copy of underlying computer

VM benefits: protection. good for research and development

System boot: starting a computer by loading the kernel. Finished by Bootstrap program

Bootstrap program: code stored in ROM that is able to locate the kernel, load it into memory, and start its execution

# Sychronization

Race condition: Several processes access and manipulate（操纵） the same data concurrently. The result is uncertain.

Critical resource: The resource that must be accessed mutual excluded

**Critical section: A segment of code in which the process is accessing critical resource.** No more than one process can execute in its critical section at the same time. Entry section and exit section.

**Mutual exclusion**: No more than one process can be in a critical section at any time.

**Progress**: If no process is executing in its critical section and there exist some processes wishing to enter, then let the one with earliest deadline enter

**Bounded waiting:** A bound must exist on the number of times that other processes are allowed to enter their critical sections after a process has made a request to enter its critical section and before that request is granted

Fairness

**Peterson's algorithm** (works for 2 processes): share 2 variables:
 `int turn`- indicates whose turn it is to enter the  critical section,
 `boolean flag[2]` - indicate if a process is ready to enter the critical section, for true it's ready

# Scheduling

Burst: Process execution consists of a cycle of CPU execution and IO wait.
I/O-bound: short bursts
CPU-bound: a few long CPU bursts

Scheduling takes place when: 

1. switches frome running to waiting
2. switches from running to ready (preemptive)
3. switches from waiting to ready (preemptive)
4. terminates

 Nonpreemptive: Once the CPU has been allocated to a process, the process keeps the CPU until it releases the CPU either by terminating or by switching to hte waiting state.

Preemptive: According to some rule, the CPU utilization of a process can be preempted.

Dispatcher: gives control of the CPu to the process selected by the short-term scheduler

Dispatch latency: time it takes for the dispatcher to stop one process and start another running (like context switch)

**Criterias:**

CPU utilization: keep the CPU as busy as possible

Troughput: num of processes that complete their execution per time unit

Turnaround time: amount of time to execute a particular process

Waiting time: amount of time a process has been waiting in the ready queue

Response time: amount of time it takes from when a request 

Turnaround time = waiting time + executing time

Necessary conditions for deadlock:

- **Mutual exclusion:** only one process at a time can use a resource
- **Hold and Wait:** a process holding at least one resource is waiting to acquire additional resources held by other processes
- **No preemption:** a resource can be released only voluntarily by the process holding it, after that process has completed its task
- **Circular wait:** there exists a set of waiting processes, making a circular request

# Memory

Program must be brought into memory and placed within a process for it to be run
CPU -> main memory and registers. cache sits between memory and registers
Multiprogramming: More than one program is allowed to get access of memory. Every process has its address space, cannot access others'

Address binding of instructions and data to memory addresses can happen at **compile time, load/link time, execution time.** Symbolic address -> relative address -> absolute address

<img src="assets/image-20251227015122244.png" alt="image-20251227015122244" style="zoom: 50%;" />

Relocation: 为了保证CPU执行指令时可正确访问内存单元，需要将用户程序中的逻辑地址转换为运行时可由机器直接寻址的物理地址。 即translation
Static: by software
Dynamic: by hardware

Base and Limit registers:

<img src="assets/image-20251227015811110.png" alt="image-20251227015811110" style="zoom:50%;" />

Logical address: generated by the CPU, also reffered as **virtual address**

Physical address: address seen by the memory unit

Logical and physical address are the same in compile-time and load-time address-binding schemes

Logical and physical address differ in execution-time address-binding scheme

**Relocation** (Translation) : Done by MMU(memory management unit), run-time mapping from virtual to pysical addresses.  Add the value in the relocation register to every address generated by a user process as it is sent to memory. User program can't see physical address

<img src="assets/image-20251227130248473.png" alt="image-20251227130248473" style="zoom:50%;" />

Dynamic loading: routine is not loaded until it's called. Better memory-space utilization, because big chunk of code may be seldom used. 代码用到了才load, 节省内存

Dynamic linking: Linking postponed (推迟) until execution time. 运行时才link库，节省磁盘内存，易更新

Memery expansion: Compaction, overlaying, swapping, virtual memory

Overlaying: 程序执行过程中，程序的不同部分在内存中相互替换。缺点：对用户不透明

Swapping: A process can be swapped temporarily out of memory to a **backing store**, and then brought back into memory for continued execution. **Transfer time** is the major part for swapping.
Backing store:  fast disk large enough to accommodate copies of all memory images for all users, must provide direct access to these memory images

Roll out, roll in: swapping variant used for priority-based scheduling algorithms. Lower-priority process is swapped out so higher ones can be loaded and executed

Kernel address in high memory, user address in low memory

Base and Limit: Use base for choosing the smallest physical address. Use limit to range the address from the base

<img src="assets/image-20251227132115397.png" alt="image-20251227132115397" style="zoom:33%;" />

Contiguous allocation: Put process into a contiguous address in memory. 

Fixed partitioning (reservation): Divide memory into fixed-sized partitions, each partition may contain exactly one process. OS keeps a table indicating which parts of memory are available and which are occpied. 
Disadvantages: internal fragmentation (lots of space not used). Degree of multiprogramming is bound (Can only put a little processes)

<img src="assets/image-20251227132457119.png" alt="image-20251227132457119" style="zoom:33%;" />

Dynamic-partition allocation (FIFO): When a process arrives, it is allocated memory from a hole large enough to accommodate it.

<img src="assets/image-20251227132949017.png" alt="image-20251227132949017" style="zoom:33%;" />

Dynamic-partition ways:
**First-fit:** Allocate the first hole that is big enough
**Next-fit:** Search from the last allocated hole
**Best-fit:** Allocate the smallest hole that is big enough. Must search entire list, unless ordered by size.
**Worst-fit:** Allocate the largest hole, must also search entire list.

First-fit is faster than best-fit.

Fragmentation:
**External Fragmentation:** Total memory space exists to satisfy a request, but it is not contiguous. Reduce external fragmentation by **compaction**: Shuffle memory contents to place all free memory together in one large block. Possible only if relocation is dynamic. (Think that you free a small chunk in heap, but it is too small for other chunks to be allocated, then it comes to be a hole in the memory)
**Internal Fragmentation:** Allocated memory may be slightly larger than requested memory. 

<img src="assets/image-20251227134145864.png" alt="image-20251227134145864" style="zoom:33%;" />

Think about segmentation. It's a method of fixed-partation allocation. It will result in both externel and internel fragmentation.

One way to solve the problem - **Paging**: Permit the logical address space of a process can be noncontiguous. Divide physical memory into **fixed-sized** blocks called **frames**, Divide logical memory into blocks of same size called **pages**. Continuous pages may not be continuous frames.

 <img src="assets/image-20251227135511505.png" alt="image-20251227135511505" style="zoom:33%;" />

Page table: virtual address -> page number -> (Through PTBR to find the PT) -> Use the page number to find the PTE -> get the PPN from PTE -> put PPN and page offset together and get the physical address. All done in MMU

# File System

File: Abstraction for disk. 一组带标识的（有名字）、在逻辑上有完整意义的信息项的序列

- write

data needed to manage open files:

- file-open count: allow removal of data when last process closes it
- disk location
- access rights

Open file locking: File locks allow one process to lock a file and prevent other processes from gaining access to it. Useful for shared files. Shared lock (readers) and exclusive lock (writer)
Mandatory 强制: Once a process acquires an exclusive lock, the OS will prevent any other process from accessing the locked file, even if other process will not modify the file
Advisory: Processes can find status of locks and decide what to do

inode：每个文件有一个存放在磁盘索引节点区的索引节点，成为磁盘索引节点，存文件信息

Allocation methods:

- contiguous allocation: external framentation, files can't grow

- extent-based system: add extents to the file

- link allocation: file is linked list of blocks. Not good for random access. Good for file grow and fragmentation
  FAT(file allocation table)

- indexed allocation: brings all pointers together into the index block. Each file has its own index block, which is an array of disk block addresses
  Sequential and fandom. More overhead

  Inode



Free-space management:

- bit map
- linked list (free list): 空闲空间表中每个条目记录一组连续空闲块的起始地址和数量

提高性能：减少磁盘访问次数

buffer cache: separate section of main memory for frequently used blocks.

read-ahead and free-behind: optimize sequential access

page cache: cache pages rather than blocks using virtual memory techniques (memory-mapped IO) 持久化与性能的 tradeoff
