# 基于 SLR 与 QAST 的简易编译器 QCompiler 实现及鲲鹏环境验证

## 实验目的

1. 根据指导书要求，实现一个面向 QL 子集的简易编译器 QCompiler。
2. 完成从源程序到 token、QAST、SLR 分析表、QTAC、符号表和 ARM64 汇编的完整编译链路。
3. 实现 A/B/C 三条可切换编译路线，并保持默认 C 路线与原有运行方式兼容。
4. 使用 qsort 程序进行本地和鲲鹏 ARM64 环境验证，检查生成汇编能否汇编、链接并正常运行。

## 实验原理

### QL 子集与编译阶段

本实验处理的 QL 子集包含变量声明、数组声明、函数定义、函数调用、赋值、数组读写、`if/else`、`while`、`return`、算术表达式和条件表达式。编译器整体 pipeline 如下：

```
QL 源程序 -> token 流 -> 语法分析 / QAST -> IR/QTAC -> 优化 -> ARM64 汇编
```

其中 token 流由 lexer 生成，SLR 表用于语法分析，IR 作为中间表示承接语义动作与后端代码生成。最终输出 `.s` 和 `.opt.s`，分别表示未优化和基础优化后的 ARM64 汇编。

### A/B/C 三条路线

指导书中给出了不同实现路线，本实验最终实现了三条路线的可切换版本：

- A 路线：递归下降 parser 构造 QAST，再由 QAST 翻译为 IR/QTAC。
- B 路线：SLR 表驱动 parser 构造 QAST，再由 QAST 翻译为 IR/QTAC。
- C 路线：SLR 表驱动 parser 在归约时直接执行语义动作，生成 IR/QTAC。

### SLR 表构造

SLR 表由文法产生式、FIRST/FOLLOW 集和 LR(0) 项目集规范族构造得到。对于 qsort 示例，当前表统计结果为：

```text
states: 125
actions: 821
gotos: 199
unresolved conflicts: 0
resolved conflicts: 2
```

两个已消解冲突分别对应括号表达式和 dangling-else。dangling-else 在 `ELSE` 上选择移进，使 `else` 绑定到最近的 `if`，符合常见语言规则。

## 核心实现与分析

### 路线选择与主流程

```cpp
IRProgram parse_by_route(char route,
                         const std::vector<Token> &tokens,
                         const std::filesystem::path &output_prefix) {
    if (route == 'A') {
        remove_file_if_exists(output_prefix.string() + ".slr");
        const QastNode qast = parse_qast_recursive_descent(tokens);
        write_file(output_prefix.string() + ".qast", qast_to_text(qast));
        return qast_to_ir(qast);
    }
    if (route == 'B') {
        const QastNode qast = parse_qast_slr(tokens);
        write_file(output_prefix.string() + ".qast", qast_to_text(qast));
        write_file(output_prefix.string() + ".slr",
                   slr_table_to_text(build_qsort_slr_table()));
        return qast_to_ir(qast);
    }
    remove_file_if_exists(output_prefix.string() + ".qast");
    Parser parser(tokens);
    write_file(output_prefix.string() + ".slr",
               slr_table_to_text(build_qsort_slr_table()));
    return parser.parse_program();
}
```

分析：

该函数是 A/B/C 三路线切换的核心。A 路线调用递归下降 parser，B 路线调用 SLR-QAST parser，C 路线沿用原有 `Parser::parse_program()`。A 路线不输出 `.slr`，C 路线不输出 `.qast`，并且在切换路线时删除可能残留的旧文件，保证阶段产物和实际执行路线一致。

主流程在生成 IR 后统一调用优化器和 ARM64 后端。因此三条路线虽然前端不同，但后端输出接口一致，实验结果可以围绕 QTAC、符号表和汇编进行统一验证。

### QAST 数据结构

```cpp
struct QastNode {
    std::string kind;
    std::string value;
    std::string type;
    std::string op;
    bool is_array = false;
    int size_bytes = 8;
    std::vector<QastNode> children;
};

QastNode parse_qast_recursive_descent(const std::vector<Token> &tokens);
QastNode parse_qast_slr(const std::vector<Token> &tokens);
IRProgram qast_to_ir(const QastNode &root);
std::string qast_to_text(const QastNode &root);
```

分析：

QAST 节点使用统一结构表示程序、声明、函数、块、语句、表达式、条件、调用和数组访问。

- `kind`：节点类别，例如 `Function`、`If`、`While`、`ArrayLoad`。
- `value`：节点名称或字面值，例如函数名、变量名、数字。
- `type`：声明或函数返回类型。
- `op`：表达式和条件中的运算符。
- `is_array`：区分数组声明、数组参数和普通标量。
- `children`：表示语法树层次关系。

采用统一节点结构可以降低 A/B 两条路线的差异。A 路线直接递归构造这些 node，B 路线在 SLR 归约时构造同样形态的 node，之后共享 `qast_to_ir` 翻译逻辑。

### 递归下降 parser 与表达式优先级

```cpp
QastNode parse_expression() {
    if (check(TokenType::Identifier) &&
        (check(TokenType::Assign, 1) || check(TokenType::PlusAssign, 1))) {
        const Token id = tokens_[pos_++];
        const Token op = tokens_[pos_++];
        QastNode assignment = make_value_node("Assign", id.lexeme);
        assignment.op = op.lexeme;
        assignment.children.push_back(parse_expression());
        return assignment;
    }
    return parse_add();
}

QastNode parse_condition() {
    QastNode condition = parse_and_condition();
    while (match(TokenType::OrOr)) {
        QastNode node = make_node("Or");
        node.children.push_back(std::move(condition));
        node.children.push_back(parse_and_condition());
        condition = std::move(node);
    }
    return condition;
}
```

分析：

A 路线不能直接使用 SLR 文法中的左递归写法，因此表达式部分采用分层优先级解析。`parse_expression()` 先识别赋值和 `+=`，再进入加减乘除解析；条件表达式则按 `||`、`&&`、`!`、关系表达式的顺序分层处理。

这一实现方式保持了 QL 子集的运算优先级，同时避免递归下降 parser 在左递归文法上无限递归。对于 qsort 中的 `j = j + 1`、`arr[j] < pivot`、`low < high` 等表达式，A 路线能够构造与 B 路线一致的语义结构。

### SLR 归约构造 QAST

```cpp
case kStatementIf:
    value.node = make_node("If");
    value.node.children = {rhs[2].node, rhs[4].node};
    break;
case kStatementIfElse:
    value.node = make_node("IfElse");
    value.node.children = {rhs[2].node, rhs[4].node, rhs[6].node};
    break;
case kPrimaryCall:
    value.node = make_value_node("Call", rhs[0].name);
    value.node.children = rhs[2].args;
    break;
case kPrimaryArrayLoad:
    value.node = make_value_node("ArrayLoad", rhs[0].name);
    value.node.children.push_back(rhs[2].node);
    break;
```

分析：

B 路线复用 `src/slr.cpp` 构造出的 SLR 表。parser 维护状态栈和语义值栈，遇到 reduce 动作时根据产生式编号构造 QAST 节点。例如 `if` 语句把条件和 then 分支作为子节点，`if/else` 再增加 else 分支；函数调用节点记录函数名和参数列表；数组读取节点记录数组名和下标表达式。

这种方式保留了 SLR 表驱动分析的形式，同时把语义动作从直接生成 IR 改为构造 QAST。由此可见，B 路线和 C 路线使用同一套文法与分析表，但中间阶段不同，符合指导书中对 SLR 到 QAST 路线的要求。

### QAST 到 IR/QTAC 翻译

```cpp
ExprResult translate_call(const QastNode &node) {
    context_.require_function_call(node.value,
        static_cast<int>(node.children.size()));
    ExprResult result;
    std::vector<ExprResult> args;
    for (const auto &arg_node : node.children) {
        args.push_back(translate_expr(arg_node));
    }
    for (const auto &arg : args) {
        append_code(result.code, arg.code);
    }
    for (const auto &arg : args) {
        result.code.push_back(IRInstruction{IROp::Par, "", arg.place});
    }
    result.place = context_.make_temp();
    IRInstruction call;
    call.op = IROp::Call;
    call.dst = result.place;
    call.callee = node.value;
    call.arg_count = static_cast<int>(args.size());
    result.code.push_back(call);
    return result;
}
```

分析：

QAST 翻译器负责把语法树转换为 `IRProgram`。函数调用翻译时，先检查函数是否已定义、参数个数是否匹配，再依次翻译参数表达式，生成 `PAR` 指令，最后生成 `CALL` 指令并把返回值放入临时变量。

同一翻译器还处理符号表、数组读写、条件跳转、循环和返回语句。数组访问会先计算地址，再生成 `Load` 或 `Store`；`if` 和 `while` 通过标签和条件跳转组织控制流。A/B 路线因此可以复用 C 路线已有的 IR、优化器和 ARM64 后端。

### 自动化路线验证

```cmake
run_qcompiler("${QCOMPILER_ROUTE_OUT}")
run_qcompiler("${QCOMPILER_ROUTE_OUT}A" --route A)
run_qcompiler("${QCOMPILER_ROUTE_OUT}B" --route B)

reject_file("${QCOMPILER_ROUTE_OUT}A.slr")
require_file("${QCOMPILER_ROUTE_OUT}B.qast")
require_file("${QCOMPILER_ROUTE_OUT}B.slr")
reject_file("${QCOMPILER_ROUTE_OUT}C.qast")
require_file("${QCOMPILER_ROUTE_OUT}C.slr")

foreach(suffix IN ITEMS qtac slr s opt.s)
    file(READ "${QCOMPILER_ROUTE_OUT}.${suffix}" default_output)
    file(READ "${QCOMPILER_ROUTE_OUT}C.${suffix}" route_c_output)
    if(NOT default_output STREQUAL route_c_output)
        message(FATAL_ERROR "default route output differs from explicit route C")
    endif()
endforeach()
```

分析：

该测试脚本验证了三类关键性质。第一，A/B/C 三路线都能成功编译 qsort 并生成必要产物。第二，A/B/C 的阶段输出符合路线定义，A 有 QAST 但没有 SLR，B 同时有 QAST 和 SLR，C 有 SLR 但没有 QAST。第三，未传 `--route` 的默认输出必须和显式 `--route C` 完全一致，确保新增路线没有破坏原有脚本和测试。

## 实验过程与思路

### 词法分析

词法分析器读取 QL 源程序并输出 token 序列。当前实现支持关键字、标识符、整数、运算符、界符、行注释和块注释，并记录每个 token 的行列号。这样在语法错误或词法错误发生时，可以给出较清晰的位置提示。

qsort 示例中，lexer 能正确识别 `int`、`void`、`while`、`return`、数组下标、函数调用和关系运算符，为后续 SLR 分析提供统一 token 输入。

### 语法分析与语义处理

C 路线采用表驱动 SLR parser。每次读取 lookahead 后，根据 ACTION 表执行 shift、reduce 或 accept；归约时直接执行语义动作，生成 IR 指令和符号表信息。

A/B 路线先构造 QAST，再统一翻译为 IR。A 路线的关键在于用递归下降实现同等语言范围；B 路线的关键在于复用同一张 SLR 表，同时把归约动作改写为 QAST 节点构造。这样三条路线在结构上有区别，但最终都进入同一 IR 后端。

### IR、优化与后端生成

IR 使用统一的 `IRProgram` 表示全局变量、函数、main 指令和符号表。QTAC 输出由 IR 格式化得到，ARM64 汇编也从 IR 生成。基础优化主要删除 `NOP`、自赋值和部分不可达指令，优化结果用于生成 `.opt.s`。

ARM64 后端生成 `_start` 入口、函数标签、栈帧、参数传递、分支跳转、数组读写和 Linux `exit` 系统调用。qsort 示例虽然没有标准输出，但程序能在目标机上正常退出，说明函数调用、递归、数组访问和控制流在汇编层面可以执行。
