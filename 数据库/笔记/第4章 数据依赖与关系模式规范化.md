# 问题

考虑关系模式 **SCT(S#, C#, Grade, Teacher, Dept)**，其中属性间的依赖关系是：

- (S#, C#) → Grade（学号+课程号决定成绩）
- C# → Teacher（课程号决定老师）
- Teacher → Dept（老师决定系别）

如果把所有信息放在一张表里，就会出现四大问题：

1. **数据冗余(Redundancy)**：同一个老师教多门课、被多个学生选，老师的Dept信息被重复存储很多次。比如100个学生选了同一门课，Teacher和Dept就重复100遍。
2. **更新异常(Update Anomalies)**：如果某个老师换了系，你需要改所有包含这个老师的元组，漏改一条就数据不一致了。
3. **插入异常(Insertion Anomalies)**：如果一个新老师还没有学生选课，你就没办法把这个老师的信息插入表里（因为S#是主键的一部分，不能为空）。
4. **删除异常(Deletion Anomalies)**：如果某门课的所有选课记录都被删了，这门课的老师信息也跟着丢了。

解决方法：分解关系模式，消除数据依赖

# 数据依赖

数据依赖(Data Dependency)：是通过一个关系中各属性值相等与否体现出来的一种数据间的相互制约关系，是现实世界中事物属性间相互联系的抽象，是数据内在的性质，是语义的体现。分为**函数依赖**和**多值依赖**

## 基本符号

统一符号：

- **R** 表示一个关系模式，完整形式为 R(U, D, DOM, I, F)
- **U** = {A₁, A₂, ..., Aₙ} 是属性全集（就是表的字段集合）
- **D** 是域集合（字段的类型集合，如 char, int）
- **DOM** 是属性到域的映射（每个字段具体的取值类型）
- **I** 是完整性约束集合（字段取值的限制）
- **F** 是R上的函数依赖集合

通常简写为 R(U, F) 或 R<U, F>，因为 D、DOM、I 对规范化理论不是核心。

<img src="assets/image-20260509140600650.png" alt="image-20260509140600650" style="zoom: 33%;" />

**内涵**是关系模式本身（表的定义和约束，不随时间变化），**外延**是关系的实例（具体的数据，会随时间变化）。

对数据完整性约束的定义：

- 静态约束：数据依赖，主键和值域的设计
- 动态约束：定义各种操作对关系值的影响

## 函数依赖（FD）

**定义4.1（函数依赖）：** 设R(U)是属性集U上的关系模式，X、Y是U的子集。如果对R的任意一个合法关系r中，不可能存在两个元组在X上的属性值相同而在Y上的属性值不同，则称X函数决定Y，或Y函数依赖于X，记作 X → Y，X 称为决定子。（只要两行数据在X列上的值一样，那它们在Y列上的值也一定一样。比如"学号→姓名"，不可能同一个学号对应两个不同姓名。）（函数就是一个x决定一个y）

两个关键点要注意：

1. **函数依赖是对所有实例的约束**，不是看某个具体表能不能找到反例。你看某个表当前没有违反，不代表FD成立；FD是由**语义**决定的。
2. PPT举了一个很好的例子：学生关系里"班级→性别"是否成立？如果学校规定男女生分班，那就成立；否则不成立。这说明**同一个关系模式，不同的语义约束下FD不同**。



**定义4.2：** 设X → Y成立：

- 如果X的任何一个真子集X'都不能决定Y（即不存在X' → Y），则称Y**完全函数依赖**于X，记作 $X \overset{f}{\rightarrow} Y$
- 否则（即存在X的某个真子集也能决定Y），则称Y**部分函数依赖**于X，记作 $X \overset{P}{\rightarrow} Y$

举个例子：在SC(Sno, Cno, Grade)中，(Sno, Cno) → Grade。单独Sno不能决定Grade，单独Cno也不能决定Grade，所以这是**完全函数依赖**。

但如果有(S#, C#) → Teacher，而实际上 C# → Teacher 就够了，那$(S\#, C\#) \overset{P}{\rightarrow} Teacher$就是**部分函数依赖**。

**完全函数依赖的决定子不包含冗余属性**，这个概念是2NF的基础。



**定义4.4：** 设X、Y、Z是R上的不同属性集合，如果 X → Y，Y → Z 成立，且 $Y\not{\rightarrow} X$（Y不能反过来决定X），则称Z**传递函数依赖**于X。

为什么要求 Y ↛ X？因为如果Y也能决定X，那X和Y就是一一对应关系，X → Z就是直接函数依赖而不是"绕了一圈"的传递依赖了。

例子：在Std(Sno, Sdept, Mname)中，Sno → Sdept，Sdept → Mname，且Sdept不能决定Sno（一个系有很多学生），所以Mname**传递函数依赖**于Sno。这个概念是3NF的基础。

## Armstrong 公理

设U是关系模式R的属性集，F是R上的函数依赖集，则有三条基本规则：

- **A1 自反率：** 如果 Y ⊆ X ⊆ U，则 X → Y 成立
- **A2 增广率：** 如果 X → Y 成立，且 Z ⊆ U，则 XZ → YZ 成立
- **A3 传递率：** 如果 X → Y 且 Y → Z 成立，则 X → Z 成立

由这三条可以推出三条导出规则：

- **合并规则：** 若 X → Y，X → Z，则 X → YZ
- **伪传递规则：** 若 X → Y，WY → Z，则 WX → Z
- **分解规则：** 若 X → Y，且 Z ⊆ Y，则 X → Z

其中合并规则和分解规则特别实用——它意味着 $X → A₁A₂...Aₖ$ 等价于 $X → A₁ 且 X → A₂ 且...且 X → Aₖ$。

逻辑导出：给定关系模式 $R<U,F>$，如果能由F根据 Armstrong 公理导出 $X\rightarrow Y$，则称 $X \rightarrow Y$ 是F的逻辑导出，记为 $F \Rightarrow X \rightarrow Y$

逻辑蕴涵：F是关系模式R上成立的函数依赖的集合，$X\rightarrow Y$是一个函数依赖，如果对于R的每个满足F的关系r也满足 $X\rightarrow Y$，记为 $F \models X\rightarrow Y$。例：$\{X\rightarrow Y,Y\rightarrow Z\}\models X\rightarrow Z$



## 闭包

**函数依赖集合的闭包 $F^+$​** ：由F出发，使用Armstrong公理能逻辑蕴涵的**所有**函数依赖的集合，叫F的闭包，记为 $F⁺$。$F⁺ = \{X → Y | F ⊨ X → Y\}$。是NP完全问题

**属性集合的闭包 $X_F^+$** ：属性集X关于F的闭包 $X_F⁺ = \{A | A ∈ U，且 F ⇒ X → A\}$。即：**从X出发，通过F能"推到"的所有属性的集合**。

**算法4.1（求属性集闭包）**：

- 输入：$X, F$
- 输出：$X_F⁺$
- 步骤：
  1. 令 $X⁽⁰⁾ = X，i = 0$
  2. 扫描$F$中每个FD $V → W$，如果 $V ⊆ X⁽ⁱ⁾$，则收集W中的属性
  3. $X^{(i+1)} = X^{(i)} ∪$ $收集到的属性$
  4. 如果 $X⁽ⁱ⁺¹⁾ = X⁽ⁱ⁾$ 或 $X⁽ⁱ⁾ = U$，终止，此时 $X⁽ⁱ⁾$ 就是 $X_F⁺$
  5. 否则 $i = i+1$，回到第2步

## 等价覆盖与最小函数依赖集

**等价覆盖（定义4.8）：** 如果两个函数依赖集F和G的闭包相等（F⁺ = G⁺），则称F等价于G，或F与G互相覆盖。

判定方法：检查F中的每个FD X→Y，Y是否属于X关于G的闭包；反过来也检查一遍。

**最小函数依赖集（定义4.9）**：F是最小函数依赖集（也叫最小覆盖 $F_{min}$）需满足三个条件：

1. **右部为单属性：** F中每个FD的右边只有一个属性
2. **左部无冗余属性：** F中不存在 X→A，使得去掉X的某个属性B后，(X-B)→A仍然成立
3. **无冗余FD：** F中不存在多余的FD，即去掉任何一个FD后闭包就变了

**定理4.2：** 每一个函数依赖集F均等价于一个最小函数依赖集$F_{min}$。

**求 $F_{min}$的三步算法：**

1. **右部拆成单属性：** 把 X → A₁A₂...Aₖ 拆成 X→A₁, X→A₂, ..., X→Aₖ
2. **消除左部冗余属性：** 对每个左部不是单属性的FD X→A，逐一检查X中的每个属性$Bᵢ$，看$(X-Bᵢ)_F⁺$ 是否包含A，如果包含就把$Bᵢ$去掉
3. **消除冗余FD：** 对每个FD X→A，令$G = F - \{X→A\}$，检查A是否在X关于G的闭包中，如果是就去掉这个FD

## 多值依赖MVD

<img src="assets/image-20260509160020116.png" alt="image-20260509160020116" style="zoom:50%;" />

理解：一个 X 不是决定**一个**值，而是决定**一组**值；而且这组值跟表里其余属性**相互独立**。给定一个 X 值，它对应的 Y 取值集合与 Z 的取值无关。

**核心性质**：

1. **成对出现**：X →→ Y ⟺ X →→ Z（Z 是剩下的属性）。
2. **FD 是 MVD 的特例**：若 X → Y，则必有 X →→ Y（反之不成立）。
3. **平凡 MVD**：Y ⊆ X，或 X ∪ Y = U（此时不带新信息）。
4. **后果**：非平凡 MVD 会逼出大量笛卡尔组合元组 → 冗余、增删改异常。FD 治不了，要靠 **4NF** 消除。

# 关系模式的规范化

范式Normal Form：满足不同程度规范化要求的关系模式的类

**1NF**（最低要求）：关系模式 R 的每个关系 r 的属性值都是**不可分的原子值**，如日期应拆成年月日三个属性



超键：K 为 R⟨U,F⟩ 中的属性或属性组合，若 **K→U ∈ F⁺**，则 K 是 R 的一个超键。

候选键：若 K→U ∈ F⁺，且**不存在 K 的真子集 K′ 使 K′→U**（最小性），则 K 是候选键。（候选键是最小的超键）

主属性/非主属性：包含在**任一**候选键中的属性是主属性，其余是非主属性。

全键：整个属性组是候选键

C1: 没出现过；C2: 只在左出现；C3: 只在右出现；C4: 左右都出现

C1和C2求并，得到的集合求闭包，如果不能推出所有属性，就把C4的加进去尝试，能推出所有属性的是候选键。



**2NF**：如果 R 中的**所有非主属性都完全函数依赖于所有候选键**，则 R∈2NF。 即：2NF 在 1NF 基础上**消除了非主属性对键的部分函数依赖**。（看箭头右边是非主属性的，左边应是候选键，且左边的真子集不能确定右边）



**3NF**：如果 R 中的**非主属性**既不部分函数依赖**也不传递函数依赖于 R 上的所有候选键**，则 R∈3NF。若 R 上每一个 FD X→A 都满足 **X 是超键或 A 是主属性**，则 R∈3NF。（看箭头右边是非主属性的，不能经过传递依赖推出右边）



**BCNF**：若对于 R 上的**任何非平凡函数依赖 X→Y，X 必包含 R 的某个候选键**，则 R∈BCNF。即：R 中每个属性都不传递依赖于 R 的候选键。消除了主属性对键的部分依赖和传递依赖，每个左部必须是超键（需要包含候选键）。（箭头右边所有的属性都不能部分或者传递依赖）



**4NF**：设 D 是 R 上成立的 FD 和 MVD 集合。如果 D 中**每个非平凡的 MVD X→→Y 的左部 X 都是 R 的超键**，那么 R 是 4NF 的模式。
